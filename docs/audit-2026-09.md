# Codebase audit and cleanup — September 2026

Record of the audit run on branch `feature/location-search` on 2026-09-16, what it
found, what was changed, and how to check the result. Written so the next person can
re-run the checks and understand why the tree looks the way it does.

Decisions with lasting consequences have their own records in `docs/adr/`:

- [ADR 0001 — Remove the London map layers and lazy-load boundary GeoJSON](adr/0001-remove-london-layers-lazy-load-boundaries.md)
- [ADR 0002 — Shim `node:process` for jest 26 instead of upgrading jest](adr/0002-jest-node-process-shim.md)
- [ADR 0003 — Route every API call through `apiHelpers`](adr/0003-api-calls-through-apihelpers.md)

## How the audit was run

All commands run from `app/` unless stated. Node 22.18, jest 26.6 (bundled with razzle 4).

```bash
npm run lint                          # ESLint, whole app
npx tsc --noEmit -p tsconfig.json     # type check (not part of the build; babel compiles)
CI=true npm test                      # jest, jsdom environment
npm run build                         # razzle production build
grep -rnE "(query|none|one|any|manyOrNone|oneOrNone|many)\(\s*\`" src   # SQL built with template literals
git diff master...HEAD                # every hunk on the branch was read
```

The frontend hunks were also reviewed independently by a subagent whose high-severity
findings were re-verified line by line before being acted on.

## Findings and what was done

### Defects introduced on the branch

| Finding | Root cause | Fix |
|---|---|---|
| `GET /api/extracts/:id` returned 404 in every configuration | `extractsRouter.ts` built the path as ``/${SUBDIRECTORY}/:extract_id``, giving `//:extract_id`. The router is already mounted at `/api`; the reverse proxy strips the subdirectory. | Route restored to `/:extract_id`. Verified with an express probe: `200`. |
| Password reset, forgotten password and leaderboard broke under a subdirectory deployment | Three raw `fetch()` calls bypassed the prefix-aware helper. | Calls routed through `apiGet` / new `apiPut` ([ADR 0003](adr/0003-api-calls-through-apihelpers.md)). |
| Commented-out HMR block with a `TODO` in `client.tsx` | Left over from the deployment commit. Violates the "no commented-out code" rule in `CODING_STANDARDS.md`. | Deleted. Client HMR is provided by razzle's dev server; nothing is lost. |
| `editHistory.test.ts` failed to run | pg-promise 10→11 pulls pg 8.17, which uses the `node:process` specifier; jest 26 cannot resolve the `node:` scheme. | `moduleNameMapper` shim ([ADR 0002](adr/0002-jest-node-process-shim.md)). API tests now declare `@jest-environment node`. |
| New ETL scripts were not in git | Root `.gitignore` had a blanket `etl/` line, so `etl/load_geonames_places.sh`, `etl/load_search_locations.sh` and `etl/load_search_locations.sql` were silently ignored although `docs/location-search.md`, migration 062 and `searchSync.ts` all reference them. | Blanket line removed; `etl/geonames_gh/` (downloaded GeoNames data) ignored explicitly. Scripts must be `git add`ed. |

### Geolocation control (`src/frontend/map/geolocation-control.tsx`)

- Header carried "copy this file into your fork" install instructions. Removed.
- A `console.warn` ran inside render behind a scaffold comment, and the error state was
  never shown to the user. Errors now log once in the position-error handler, and the
  locate button is disabled with the reason as its tooltip.
- `headingRef` was initialised to `0`, so the `??` fallback to the GPS heading could
  never fire; devices without a compass had an arrow locked north. Initialised to `null`.

### Search (`search-box.tsx`, `search-results-layer.tsx`)

- A `{error: 'Database error'}` response (HTTP 200) rendered as "No matches found".
  There is now a distinct error state and message.
- Empty or whitespace queries no longer send a request.
- `fetching` state was set but never read; the button now shows "Searching…" and is
  disabled while a request is in flight.
- `e.keyCode` replaced with `e.key === 'Escape'`.
- The hover-highlight effect depended only on `hoveredId`, so markers rebuilt for a
  new result set lost their highlight. `results` added to the dependencies.

### Configuration and hygiene

- `.eslintrc` listed `eslint:recommended` twice. The second listing re-enabled the base
  `no-unused-vars` on TypeScript files, producing 259 false errors on unused parameters
  in type signatures. Deduplicated, `no-unused-vars` turned off in favour of the
  TypeScript rule, stale `ecmaVersion: 6` raised to 2020.
- `package.json` name changed from `colouring-london-app` to `colouring-ghana-app`.
- Tab-indented lines in `razzle.config.js` normalised to four spaces.
- A stray unix socket file `app/null` was deleted.

### London dead weight

Seven London-only boundary layers were still mounted on the map and each fetched its
GeoJSON on mount regardless of whether the layer was toggled on. See
[ADR 0001](adr/0001-remove-london-layers-lazy-load-boundaries.md) for the removal and
the lazy-loading design that replaced it.

## Reproducing the verification

```bash
cd app
npm ci
npm run lint 2>&1 | grep problems        # expect: ✖ 215 errors-ish, 3563 warnings-ish
CI=true npm test                          # expect: Test Suites: 3 passed, 3 total
npm run build                             # expect: "Compiled server default build successfully."
```

Express probe for the extracts route, without a database:

```bash
node -e "
const express=require('./node_modules/express');const app=express();const r=express.Router();
r.get('/:extract_id',(q,s)=>s.send('hit '+q.params.extract_id));app.use('/api/extracts',r);
const srv=app.listen(0,async()=>{const res=await fetch('http://127.0.0.1:'+srv.address().port+'/api/extracts/1');
console.log(res.status,await res.text());srv.close();});"
# expect: 200 hit 1
```

In a browser with the app running: open the map, open DevTools → Network, filter
`geojson`. Expect no requests until "Regions" or "Districts" is toggled on, then one
request per layer, never repeated on further toggles.

Not verified in a browser during the audit (no database available in the session):
region/district toggle, the search error and loading states, the disabled locate button.

## Known debt left in place

Report-only items, deliberately not changed in this pass:

- `tsc --noEmit` still reports ~40 inherited errors: `express-session` `user_id` typing,
  `@types/node@12` versus `@types/webpack-env`, a bad import in `category-view-props.ts`.
  The build uses babel so these do not gate anything, but there is no type-safety net.
  Follow-up: bump `@types/node` to 22 and add an `express-session` type augmentation.
- 3.5k ESLint warnings, mostly quotes and indentation, auto-fixable. Do this as a
  single dedicated commit, never mixed into feature work.
- `.travis.yml` pins Node 12. The runtime is Node 22 and pg-promise 11 needs ≥14.
- London content remains in `welcome.tsx`, `privacy-policy.tsx`, `supporter-logos.tsx`
  and some data-field help text (33 references). This is localisation work, not cleanup.
- The district layer attribution credits OCHA/GSS COD-AB, but `Gh_adm_bnd_L2.geojson`
  carries an ArcGIS-style schema (`DIST_NAME`, `Shape_Leng`) unlike the L1 file. The
  source should be confirmed before the attribution is trusted.
- Search result list items are mouse-only (no `tabIndex` or key handler).
- Geolocation starts `watchPosition` on page load, so every visitor gets a browser
  location prompt. Starting on the first button click would be less intrusive.
- Migration 061 uses `ADD COLUMN IF NOT EXISTS` but `ADD CONSTRAINT` without a guard.
  Harmless under the run-once migration flow.
