## Problem Statement

The Colouring Ghana map is slow. Every category colouring, the building outlines, the number labels and the
selection highlight are pictures drawn on the server by Mapnik, one tile at a time, from the database. Switching
from "age" to "construction material" refetches every tile on screen. Most visitors are on Android phones over
mobile data, where bandwidth rather than latency is the limit, so a map that redraws pictures for every change is
expensive to use and slow to become interactive.

The same picture tiles also block the analytical platform: a query result cannot be drawn over raster tiles in the
browser, packs cannot carry raster tiles offline, and the colour rules live in two places (Mapnik XML on the server,
legend config in the browser) that can drift apart.

Contributors depend on one behaviour above all: after saving an edit, the building's new colour appears on the map
within seconds. Any replacement must keep that, and everything else the map does today, without a period where the
old map is unavailable as a fallback.

## Solution

Replace Leaflet plus Mapnik raster tiles with MapLibre GL drawing vector tiles from a single PMTiles archive built
nightly, behind a map-stack flag so the two stacks coexist until a written parity checklist passes in production and
a four-week soak completes.

From the user's side:

- The map looks and behaves the same: same colours, legend, themes, boundaries, labels, search pins, location
  control, zoom limits and initial view. Category switching becomes instant because the browser recolours shapes it
  already has.
- Edits still appear at once. The browser draws an edits-since overlay: the small set of buildings changed after the
  nightly archive was built, fetched from a read-only endpoint and coloured by the same rules.
- Less data moves over the connection. The archive is read in small range requests; a category switch fetches
  nothing new.
- Nobody is switched without a gate. First the new map is opt-in; testers on their own devices, including an
  Android phone on mobile data, work through the parity checklist. Then the default flips with opt-out kept. After
  four weeks with no blocking defect, the old stack is removed (the flag-removal ticket).
- The basemap stays OpenStreetMap raster tiles in this epic; a self-hosted Ghana basemap is a later decision
  (OD-11).

## Implementation Decisions

Numbered decisions carry the grilling reference (G1–G11) or the ADR they come from. Decisions marked "spec" were
made here to close a gap and are open to the product owner's veto.

### Delivery shape

1. **Two stacks behind a map-stack flag; Leaflet tree untouched.** (ADR-0018, G8) The MapLibre map is a sibling of
   the Leaflet map, selected at render time. Nothing in the Leaflet tree, the Mapnik tile server or the tile-cache
   expiry changes in this epic; the flag-removal ticket removes them after the gates.
2. **Flag resolution is one pure function.** (G8) Inputs: environment default (`MAP_STACK`, values `leaflet` |
   `maplibre`, default `leaflet` when unset), the `?map=` query parameter, and a functional cookie. Rules: the
   environment default applies when nothing else is set; an explicit `?map=` sets the cookie and wins for that
   request; the cookie wins over the environment default. The server render and the client resolve with the same
   function and the same inputs, so hydration never disagrees. The server injects the environment default into the
   preloaded state; the client never reads server environment variables directly.
3. **Active-stack indicator during soak.** (G8; spec) The layer-options panel shows the active stack and the
   archive's "as of" time, with a link that switches to the other stack via `?map=`. This is the opt-in mechanism
   for gate 1 and the opt-out for gate 2. It goes with the flag-removal ticket.
4. **Gates and sign-off.** (ADR-0027) Gate 1: production default Leaflet, MapLibre opt-in, checklist run by the
   product owner plus two planners or contributors on their own devices, one Android phone on mobile data; passes
   when every item is ticked and no blocking defect is open. Gate 2: default flips to MapLibre with opt-out;
   benchmarks recorded at the flip; four weeks with no blocking defect. Each gate: owner sign-off, date and
   checklist version in the feature doc. Blocking resets the clock; cosmetic does not.
5. **Branching.** The integration branch is `feature/maplibre-migration`; ticket branches come off it. The base
   branch is not reorganised by this work (see `tasks/lessons.md`).

### Archive and export job

6. **One PMTiles archive, one `buildings` layer.** (ADR-0023, G2) Properties: `building_id` plus every attribute any
   of the category colourings reads, plus `location_number` for number labels. The attribute list is derived from
   the style config so the two cannot drift; the export checker asserts the archive's property keys equal that
   list plus `location_number`. Demolished buildings (a demolition date set) are excluded from the archive as they
   are from today's tiles.
7. **Feature id is `building_id`.** (spec) The archive's features carry `building_id` as the vector-tile feature id
   (tippecanoe id attribute) and the source promotes it, so MapLibre feature-state addresses a building by id
   across tiles and zoom levels. Selection highlight and base-feature hiding both depend on this.
8. **Zoom range.** (G-assumption) Data from zoom 9, tippecanoe maximum zoom 16, MapLibre overzoom to 19; minimum
   map zoom 7, maximum 19. Building outlines visible from zoom 14, colouring from zoom 9, numbers from zoom 17,
   matching today. Simplification and small-feature dropping below legible zoom are tippecanoe settings whose exact
   values are benchmarked (method v1) and recorded with the archive's provenance.
9. **Clippable for packs.** (FR-10.2, G-assumption) The archive is a standard PMTiles v3 file with tile
   compression that `pmtiles extract` can clip by bounding box without a rebuild. No pack is built in this epic.
10. **Export job: one transaction, one read.** (ADR-0024, G4) `REPEATABLE READ` read-only transaction; `now()`
    recorded from inside it as the "as of"; one export query to FlatGeobuf driven from the session holding the
    transaction; PMTiles derived from the FlatGeobuf (ADR-0025, G5); artefacts written to a temporary path and
    renamed into place; manifest written last. Dedicated read-only export role; generous timeout; `nice`/`ionice`;
    quiet window (Unknown — to be confirmed by the product owner against contribution patterns); no statement
    timeout. M1 adds GeoParquet from the same FlatGeobuf; nothing in E0 pre-empts OD-6.
11. **Tools.** (ADR-0025, G5) `ogr2ogr` writes FlatGeobuf in EPSG:4326; tippecanoe (Felt fork) writes PMTiles
    directly with the property list restricted to decision 6. Production GDAL version is Unknown — to be confirmed
    by the maintainer; E0 needs only FlatGeobuf support (present from GDAL 3.1). Both pinned in the inventory and
    installed by the provisioning script.
12. **Manifest.** (ADR-0024) JSON, versioned schema (`format_version`), fields: `as_of` (ISO 8601 UTC, the
    transaction timestamp), `artefacts[{path, bytes, sha256}]`, `tools{gdal, tippecanoe}`, `layer_versions`,
    `feature_count`. The archive's PMTiles metadata carries the same `as_of`. The versioned format description
    lives in `docs/specs/` per the epic guide; changing it later is an ADR.
13. **Artefact naming and retention.** (spec) The archive file name includes its `as_of`, so its URL is immutable
    and can carry a long `Cache-Control`; the manifest lives at a fixed URL with `no-cache` and an ETag, so clients
    always revalidate it. The job keeps the previous archive until the next successful run so a session that read
    the earlier manifest keeps working; older archives are deleted by the job.
14. **Serving.** (G7) Archive and manifest are served by the existing Express static handler, which already
    supports Range and ETag, under a dedicated static URL prefix distinct from `/tiles/` and honouring the
    subdirectory deployment prefix. No CDN in E0. The artefact directory is configured by one environment
    variable, documented beside the tile-cache settings it will eventually replace.
15. **Observability.** (ADR-0022 follow-up) The job logs start time, `as_of`, feature count, artefact sizes and
    checksums, duration and exit status. A failed run leaves the previous manifest in place (never a partial
    publish) and exits non-zero. A stale-manifest alert (older than a configurable age) is recorded as a follow-up
    in the feature doc, not built here.

### Style config, legend and map layers

16. **One style config generates expressions and legend.** (ADR-0023, G2) Each category map definition holds the
    attribute name, the value-to-colour mapping (categorical) or bands (numeric), and legend metadata. One function
    returns legend entries and a MapLibre `match` or `step` expression from the same definition. Every active category
    colouring (39 unique today; see Further Notes on the count) and the 3 base themes (`light`, `night`,
    `night_outlines`) are generated variants; `night_outlines`
    remains unreachable from the theme switcher as it is today.
17. **Layers ported one-to-one with the React binding.** (ADR-0026, G9) Base building fill, category colouring,
    highlight, number labels, city boundary, region and district boundaries, search pins, and the geolocation
    control are components over `@vis.gl/react-maplibre` `Map`, `Source`, `Layer` and `useMap`, keeping the shape
    of the existing components. Boundary layers become GeoJSON sources with fill-less line layers and symbol layers
    for labels; the zoom-dependent label rules (region labels at zoom ≤ 11, district labels at zoom ≥ 12) become
    layer zoom ranges; GeoJSON is still fetched only on first enable. Search pins and the geolocation marker become
    markers or symbol layers with the same icons, colours, hover emphasis and fit-to-bounds behaviour.
18. **Peer check for the binding.** (ADR-0026, G9) The port verifies `@vis.gl/react-maplibre`'s peer range against
    React 17 and TypeScript 4.2 before any layer is written and records the outcome in the inventory. If the check
    fails, the fallback is a thin component wrapper over `maplibre-gl` with no framework upgrade in E0, as ADR-0026
    says. Confirmed by the product owner on 2026-09-16; the grilling record carries a correction note on its row 9.
19. **Basemap.** (G6) OpenStreetMap raster tiles as a MapLibre raster source at the same URL and attribution as
    today; the night theme is applied with raster paint properties instead of a CSS filter. OSMF tile policy is an
    inherited compliance item recorded in the inventory; OD-11 (self-hosted Protomaps Ghana extract) is previewed
    with planners during soak and decided by M4.
20. **Themes.** Theme switch keeps light and night with the same background colours; the switch does not reset
    selection or layer toggles.

### Selection, highlight and multi-edit

21. **Click resolves locally.** (G3, FR-14.11.b spirit) A map click runs a hit-test against the rendered building
    layers (archive and overlay) at the click point and yields a `building_id`. The map no longer calls the
    server locate endpoint. When several features hit (overlay over base), the overlay feature wins.
22. **Map callback contract changes from building record to building id.** (spec) The map reports the clicked
    building id; the app shell loads the building record with the existing building-by-id API (the same call used
    when a building URL is opened directly), then selects or toggles as today. Multi-edit uses the same hit-test and
    sends the pending edit to that id, as today.
23. **Highlight via feature-state.** (G3) The selected building is highlighted by setting a `selected` feature-state
    on its id, styled by a highlight layer over the colouring; no per-selection tile fetch.
24. **Clicking with building layers hidden selects nothing.** (spec; accepted 2026-09-16) With "Editable
    Buildings" off the building layers are not rendered, so the hit-test finds nothing and a click selects nothing.
    Today a click still selects an invisible building through the server. This is a documented expected difference,
    listed as such in the parity checklist; it is not a parity defect.

### Edits-since overlay

25. **Endpoint.** (ADR-0022, G1) `GET /api/buildings/edited-since?after=<ISO 8601 timestamp>` returns a GeoJSON
    FeatureCollection of buildings whose latest revision timestamp is at or after `after` (inclusive `>=`, so an
    edit at the export instant is never lost). Properties: `building_id`, the styled attribute set of decision 6,
    `location_number`, and a `demolished` flag for buildings with a demolition date. No username, user id or
    revision metadata. Validation: `after` must parse as a timestamp; otherwise 400. Row cap (constant, recorded in
    the feature doc) enforced server-side and reported to the client in the response (`truncated: true` and the cap
    value). Short per-query statement timeout. `Cache-Control` with a short TTL, so responses for the same `after`
    are cacheable (NFR-2.6). Called through the shared API helpers (ADR-0021).
26. **Grace margin.** (spec) The client asks for edits from the manifest `as_of` minus a fixed margin (60 seconds)
    to cover an edit transaction that began before the export snapshot and committed after it. Duplicates are
    harmless: the overlay draws over the base. The margin is a named constant.
27. **Client behaviour.** (ADR-0022) The overlay is a GeoJSON source with fill and outline layers per theme using
    the same style expressions as the archive, ordered above it. For every overlay feature the base feature with
    the same id is hidden via feature-state (`superseded`), so a stale colour never shows through. Demolished
    features hide the base and draw nothing. The manifest is fetched at page load and after each save; the overlay
    is refreshed after the contributor's own save and on a fixed interval (5 minutes) while the tab is visible.
    Overlay fetch failure leaves the archive rendering and logs an error without coordinates; a truncated overlay
    shows a short notice in the layer-options panel.
28. **Offline.** No overlay when the network is absent; the archive already loaded keeps rendering (FR-9.3
    wording). Packs and pack "as of" are out of scope here.

### Privacy and disclosure

29. **Nothing new leaves the browser.** Geolocation control unchanged in data flow (FR-14.11.d; any network or
    storage write needs a new ADR). Click coordinates no longer leave the browser at all (local hit-test). New
    outbound requests: manifest and archive range requests to the site's own host; the edited-since endpoint with
    a timestamp only.
30. **Notice items for M5.** (G6, G8, FR-14.11.c) Recorded in the feature doc for the M5 privacy notice: the OSM
    tile host sees zoom-19 tile requests today; after the migration the site host sees archive range requests
    (tile-level location exposure moves from the tile server to the archive host); the `?map=` cookie is a
    functional cookie. `RECENTER_ZOOM` remains the only lever on that exposure and is not changed here.
31. **Export role.** (NFR-3.5) Read access to buildings tables, geometries, planning data used by colourings and
    reference layers only; no access to users or the edit log's identity columns.

## Testing Decisions

What makes a good test here: it asserts behaviour a user or a sibling artefact can observe (a colour on the legend
matching a colour in the expression, a manifest timestamp matching the archive's, an edit appearing on the map,
the same building found by both stacks), not the internals of a component or the exact shape of a MapLibre style
object. MapLibre needs WebGL, so nothing in the map itself runs under jest's jsdom; pure logic runs under jest,
browser behaviour under Playwright, and the parity checklist stays the human gate.

Seams (agreed 16 September 2026; existing seams preferred, one new seam at the highest point, per seam type):

| # | Seam | Runner | What is asserted | Prior art |
|---|---|---|---|---|
| 1 | Style config: one function turns a category map definition into legend entries plus a MapLibre expression | jest | For every active category map definition (39 unique colourings today), every legend colour appears in the expression and every expression colour appears in the legend; the derived attribute list is exactly the set of attributes the definitions read | Land-use domain-logic test (pure function, `@jest-environment node`) |
| 2 | Export job, run against the dev database | Shell plus a small checker | Manifest `as_of` equals the transaction's recorded timestamp; FlatGeobuf and PMTiles derive from that one read (same feature count and ids, same `as_of` in archive metadata); checksums recompute; archive property keys equal the style config's attribute list plus `location_number`; a forced failure leaves the previous manifest in place | None; new seam |
| 3 | Edits-since service, data access mocked | jest | Row cap enforced and reported; timestamp validation; inclusive `>=` boundary at the cut-off; no username or contributor identity in the output; demolished flag present | Edit-history service test (manual data-access mock, `@jest-environment node`) |
| 4 | Map-stack flag resolver: pure function of environment default, query parameter and cookie | jest | Environment default applies when nothing else is set; explicit query parameter sets the cookie; cookie precedence over environment default; server and client resolution agree for the same inputs | None; pure function, same shape as seam 1 |
| 5 | Browser smoke via Playwright against the dev server, differential while both stacks coexist | Playwright | Same fixed path on both stacks via the flag: building id from the local hit-test (MapLibre) equals the id from the locate endpoint (Leaflet) at fixed coordinates; legend and colour state after each category switch match; on MapLibre an edit appears in the overlay without reload | None; shares the runner and the path file with the benchmark method |

Shared path definition: the smoke test and the benchmark script read one checked-in path file (initial viewport,
two named places, zoom steps 12 to 19, category pair age then construction material, one fixed building), so the
differential test and the benchmark cannot drift apart.

Runner notes: jest 26 under razzle (ADR-0020 shim applies; API tests carry the node environment docblock);
Playwright is a new dev dependency (inventory row already planned). The Playwright suite runs on demand against a
dev server with the dev database, not in the unit test command.

The parity checklist below is the acceptance test for gate 1 and is not automated.

## Parity checklist (v1, 2026-09-16)

Copied into the feature doc per run with tester role, device, connection type, date and a tick or a defect id
(blocking or cosmetic) per row. Every row must be ticked on at least one Android phone over mobile data.

Colouring and legend
- [ ] Each active category colouring (39 today; the list is generated from the style config) renders the same
      colours as the old map at zooms 9, 12, 14, 17 and 19 (screenshot pair per colouring, same view).
- [ ] Legend title, description and disclaimer shown for each colouring; legend colours match the map.
- [ ] Category select in the legend switches colouring without a reload; legend collapse and expand work.

Themes and base
- [ ] Light and night themes switch; map background colour matches the old map in each.
- [ ] Building outlines appear from zoom 14; colouring from zoom 9; basemap and attribution present.
- [ ] "Editable Buildings" toggle hides and shows the building layers.

Boundaries and labels
- [ ] Region boundary toggles on and off; region labels show at zoom ≤ 11 only.
- [ ] District boundary toggles on and off; district labels show at zoom ≥ 12 only.
- [ ] City boundary drawn on load.
- [ ] Building numbers shown from zoom 17.
