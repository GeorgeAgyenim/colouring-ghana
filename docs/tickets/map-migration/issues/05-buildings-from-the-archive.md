## Parent

Map migration epic (FR-9; ADR-0009, ADR-0018). Spec: `docs/tickets/map-migration/PRD.md`.

## What to build

On the MapLibre stack a visitor sees the buildings coloured exactly as on the old map, from the nightly archive.
The client reads the manifest at page load, opens the archive it lists as a PMTiles vector source with
`building_id` promoted as the feature id, and renders: the base building fill per theme from zoom 14, the selected
category colouring from zoom 9 using the expression generated by the style config, and number labels from zoom
17. Switching category in the legend recolours instantly with no new tile fetch. The "Editable Buildings" toggle
hides and shows the building layers. The layer-options panel shows the archive's "as of" beside the active stack.

## Acceptance criteria

- [ ] For every active category colouring, a screenshot pair (old and new stack, same view) at zooms 9, 12, 14, 17
      and 19 shows the same colours; the pairs are kept as evidence for the parity checklist.
- [ ] Category switch triggers no new archive range requests beyond those already in flight (network capture).
- [ ] Base fill from zoom 14, colouring from zoom 9, numbers from zoom 17; overzoom from 16 to 19 renders cleanly.
- [ ] Both themes recolour base fill and outlines as today; "Editable Buildings" off hides all building layers.
- [ ] "As of" shown in the layer-options panel equals the manifest's `as_of`.
- [ ] Bytes transferred for the benchmark path segment "initial load" and "category switch" recorded informally in
      the feature doc (the formal numbers come from ticket 12).
- [ ] Layer components keep the shape of the existing ones (one component per layer, declarative source and
      layer); module headers cite FR-9.2, FR-9.5, ADR-0023; `CHANGELOG.md` updated.
